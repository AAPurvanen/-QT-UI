## 1. 核心电路设计

### 1.1 系统整体架构

本系统以 STC89C52RC 单片机为核心控制器，外接超声波测距模块（HC-SR04）、人体红外传感器（HC-SR501）、LCD1602 显示屏、三色 LED 指示灯、蜂鸣器以及按键输入，构成一套完整的距离监测与安全预警系统。

```
                    ┌─────────────────────────┐
                    │       STC89C52RC        │
                    │        (主控MCU)         │
                    │                         │
  HC-SR04 ──────┤ P2.0(TRIG)               │
  (超声波)     ──┤ P2.1(ECHO)           P0   ├── LCD1602 D0~D7
                    │                     P3.4 ├── LCD1602 EN
  HC-SR501 ──────┤ P2.2(IR_IN)          P3.5 ├── LCD1602 RS
  (人体红外)       │                         │
                    │                     P1.3 ├── 红色LED (危险报警)
  三色LED ────────┤ P1.4                    │
                    │ P1.5                 P2.3 ├── 蜂鸣器 (ULN2003)
                    │                         │
  按键S14 ────────┤ P3.2                 P2.6 ├── 数码管段选(禁用)
  按键S18 ────────┤ P3.3                 P2.7 ├── 数码管位选(禁用)
                    └─────────────────────────┘
```

### 1.2 引脚分配表

| 引脚 | 方向 | 连接对象 | 功能说明 |
|------|------|----------|----------|
| P2.0 | 输出 | HC-SR04 TRIG | 超声波触发输入 |
| P2.1 | 输入 | HC-SR04 ECHO | 超声波回波输出 |
| P2.2 | 输入 | HC-SR501 | 人体红外检测信号 |
| P1.3 | 输出 | 红色 LED | 危险报警指示 |
| P1.4 | 输出 | 黄色 LED | 注意警示指示 |
| P1.5 | 输出 | 绿色 LED | 安全状态指示 |
| P2.3 | 输出 | 板载蜂鸣器 | ULN2003 驱动，低电平导通 |
| P2.6 | 输出 | 数码管段选锁存器 | 初始化时拉低，释放 P0 总线 |
| P2.7 | 输出 | 数码管位选锁存器 | 初始化时拉低，释放 P0 总线 |
| P3.2 | 输入 | 按键 S14 | 模式切换（监控/静默/记录） |
| P3.3 | 输入 | 按键 S18 | 短按=上翻，长按=下翻 |
| P3.4 | 输出 | LCD1602 EN | 使能信号 |
| P3.5 | 输出 | LCD1602 RS | 命令/数据选择 |
| P0 | 双向 | LCD1602 D0~D7 | 8 位数据总线 |

### 1.3 关键电路设计要点

**（1）总线复用处理**  
TX-1C 开发板的 P0 口同时连接 LCD1602 数据线和板载数码管的段选/位选锁存器（74HC573）。为避免冲突，初始化时需将 `DULA`（P2.6）和 `WELA`（P2.7）置为低电平，关闭数码管锁存器输出，将 P0 总线完全交给 LCD1602 使用。

**（2）蜂鸣器驱动电路**  
板载蜂鸣器通过 ULN2003（达林顿管阵列）驱动，采用低电平导通方式。软件中 `BEEP_Set()` 函数进行逻辑取反：传入 `1`（响）→ 输出 `0`（低电平导通）。

**（3）超声波接口设计**  
HC-SR04 的 TRIG 和 ECHO 引脚分配在 P2 端口（P2.0/P2.1），而非默认的 P1 端口，原因在于 TX-1C 开发板的 P1 口已连接板载 LED，使用 P1 口会造成功耗和显示干扰。

**（4）LCD 与按键共用引脚**  
LCD1602 的控制引脚 EN（P3.4）和 RS（P3.5）在 TX-1C 开发板上同时连接了 S15/S17 和 S16/S19 按钮。使用 LCD 时操作这些按钮会导致总线冲突，需在说明文档中明确警告。

### 2.2 核心选型分析

**STC89C52RC**：作为 51 单片机经典款型，具备足够的外设资源（GPIO、定时器、UART），兼容 8051 指令集，开发工具链成熟（Keil C51），成本极低，适合嵌入式入门和工业控制场景。

**HC-SR04**：相比红外测距模块，超声波不受环境光干扰、可测量透明/深色物体；相比激光测距成本仅 1/10。2cm~400cm 量程完全覆盖本项目的应用场景（安全距离阈值设在 30cm/50cm/100cm）。

**LCD1602 vs OLED**：当前主项目使用 LCD1602 作为显示输出，因为其 8 位并行接口编程简单、显示稳定。OLED 模块（SH1106/SSD1306，I2C 接口）作为扩展功能已编写驱动代码和独立测试程序，可在后续迭代中替换以支持中文显示和图形界面。

### 4.2 超声波测距模块（`drv_ultra.c`）

#### 核心测量原理

HC-SR04 测距基于声波飞行时间法（Time of Flight）：
```
距离(cm) = 高电平时间(μs) × 声速(340m/s) / 2
         ≈ 计时器计数值 × (1/11.0592MHz × 12) × 0.034 / 2
         ≈ 计时器计数值 / 59   (整数运算，避免浮点)
```

#### 测量过程

```
TRIG ────┬───┬────  15μs 高电平触发
         │   │
         │   └────────────────────────────────────
         │
ECHO ───────────────┬───────────────────┬──
                    │    高电平持续时间    │
                    │  = 声波飞行时间     │
                    └───────────────────┘
                    ↑                 ↑
              定时器开始          定时器停止
              (TH0=TL0=0)     (读取计数值)
```

#### 异常处理机制

```c
// 前置 ECHO 卡死检测
if(ECHO == 1) {
    发送复位脉冲（20μs高电平）
    等待 ECHO 回落
    若超时则放弃本次测量
}

// 连续超时自动复位
if(raw == 400) {  // 超时返回400
    timeoutCount++;
    if(timeoutCount >= 3) {
        Ultra_Reset();   // 强制复位传感器
        return 800;      // 特殊标记：复位中
    }
    return lastValidDist;  // 返回上次有效值
}

// 滑动均值滤波
filterBuf[5] 循环缓冲区
首次调用：用第一个有效值填充整个缓冲区
后续：新值写入 → 计算 5 个值的算术平均
```

### 4.3 报警逻辑模块（`app_alarm.c`）

#### 四级报警分级策略

```c
Alarm_Check(dist, human) {
    // 传感器复位中
    if(dist >= 800) → 显示 "SENSOR RESET..."

    // 强制报警：有人 + 距离 < 50cm
    if(human && dist < FORCE_DIST)  → 红灯 + 蜂鸣快闪(400ms周期) + 记录

    // 普通报警：距离 < 30cm
    else if(dist < WARN_DIST)       → 红灯 + 蜂鸣慢闪(1.2s周期) + 记录

    // 注意警示：30cm ≤ 距离 < 100cm
    else if(dist < SAFE_DIST)       → 黄灯 + 蜂鸣关

    // 安全状态：距离 ≥ 100cm
    else                            → 绿灯 + 蜂鸣关
}
```

#### LCD 显示格式

| 行 | 监控模式示例 | 静默模式示例 |
|----|------------|------------|
| L1 | `MONI DIST:042cm` | `SLNT DIST:042cm` |
| L2 | `HUMAN:Y FORCE` | `HUMAN:N ALARM` |
| L2 状态 | FORCE/ALARM/WARN/SAFE | 四种状态 |

#### 报警记录环形缓冲区

```c
#define RECORD_MAX  10
typedef struct {
    u16 dist;      // 报警距离
    u8  hour;      // 时
    u8  min;       // 分
    u8  sec;       // 秒
} AlarmRecord;

// 静态时间戳递增（每次报警自增1秒）
static u8 sec=0, min=0, hour=0;

// 环形写入
alarmBuf[recIndex] = {dist, hour, min, sec};
recIndex = (recIndex + 1) % RECORD_MAX;
```

### 4.5 蜂鸣器告警模式（`drv_led_buzz.c`）

```c
BEEP_AlarmMode(mode)
│
├─ mode=0 (关闭) → BEEP=1 (高电平=关)
│
├─ mode=1 (普通告警)
│   ├─ 周期约1.2s (依赖主循环50ms周期)
│   ├─ 响3次 → 停1次 → 循环
│   └─ beepCounter % 4 == 0 时关
│
└─ mode=2 (强制告警)
    ├─ 周期约400ms
    └─ beepCounter 奇偶交替通断
```

### 4.6 LCD1602 驱动（`drv_lcd1602.c`）

初始化时序：
```
上电等待 20ms → 0x38(8位/2行/5x8) → 0x0C(开显示/关光标) → 0x06(右移) → 清屏
```

支持 API：
- `LCD_Init()` — 初始化（先关闭数码管锁存器释放 P0）
- `LCD_Clear()` — 清屏
- `LCD_SetCursor(row, col)` — 光标定位
- `LCD_ShowChar(row, col, ch)` — 显示字符
- `LCD_ShowString(row, col, str)` — 显示字符串
- `LCD_ShowNum(row, col, num, len)` — 显示数字（前导补零）

## 7. 调试问题和优化的改进

### 7.1 调试过程中遇到的问题

#### 问题1：P0 总线冲突导致 LCD 显示异常

**现象**：LCD1602 上电后显示乱码或无法显示内容。  
**根因**：TX-1C 开发板的 P0 口同时连接 LCD1602 数据线和板载数码管的 74HC573 锁存器输出。数码管锁存器默认使能，其输出干扰了 LCD 的数据总线。  
**解决方案**：在 `LCD_Init()` 中首先执行 `DULA=0; WELA=0;` 关闭两个锁存器，将 P0 总线控制权完全交给 LCD1602。

```c
void LCD_Init(void) {
    DULA = 0;   // 关闭段选锁存器
    WELA = 0;   // 关闭位选锁存器
    P0 = 0x00;  // P0 输出低电平
    // ... 后续 LCD 初始化
}
```

#### 问题2：HC-SR04 ECHO 引脚卡死

**现象**：连续多次测距返回 400（超时），传感器失效。  
**根因**：HC-SR04 在某些异常情况下（如上电时序异常、强电磁干扰）会保持 ECHO 引脚为高电平，导致单片机一直等待测距完成。  
**解决方案**：在 `Ultra_MeasureOnce()` 中增加前置 ECHO 电平检测和复位脉冲发送机制。同时增加连续超时计数，超 3 次自动执行完整复位流程。

#### 问题3：超声波测距数值跳变

**现象**：障碍物静止时，显示的距离值仍在小范围内来回跳动。  
**根因**：超声波受环境噪声（多径反射、串扰）影响，单次测量存在 ±2~3cm 的随机误差。  
**解决方案**：引入 5 级滑动均值滤波缓冲区，有效抑制随机噪声。

```c
#define FILTER_N   5
static u16 idata filterBuf[FILTER_N];

// 每次测量后更新缓冲区并计算平均值
filterBuf[filterIdx] = raw;
filterIdx = (filterIdx + 1) % FILTER_N;
// 计算滑动平均
for(i = 0; i < FILTER_N; i++) sum += filterBuf[i];
return (u16)(sum / FILTER_N);
```

#### 问题4：蜂鸣器告警节奏与主循环周期耦合

**现象**：蜂鸣器告警的响/停节奏依赖于主循环的调用频率。  
**根因**：`BEEP_AlarmMode()` 函数通过内部计数器 `beepCounter` 配合取模运算控制通断，其节奏严格依赖于主循环周期（50ms）。  
**解决方案**：在代码注释中明确标注了这种耦合关系，并校准了计数器阈值使得告警节奏符合设计要求（普通告警 ~1.2s 周期，强制告警 ~400ms 周期）。

### 7.2 已实施的优化

| 优化项 | 优化前 | 优化后 | 效果 |
|--------|-------|--------|------|
| 测距滤波 | 单次测量直接输出 | 5 级滑动均值滤波 | 数值跳动从 ±3cm 降至 ±1cm |
| 传感器异常 | 无处理，直接卡死 | 前置检测 + 自动复位 | 系统鲁棒性显著提升 |
| 按键消抖 | 无消抖 | 20ms 软件消抖 | 消除按键抖动误触发 |
| LCD 显示 | 未关闭数码管 | 初始化关闭锁存器 | 解决乱码问题 |
| 距离换算 | 浮点运算 | 整数除法 `time/59` | 减少代码体积，提高运行速度 |
| 代码结构 | 单文件 | 分层驱动 + 应用分离 | 模块可复用，维护性提升 |

## 8. 设计工作总结与亮点

### 8.1 工作总结

本设计基于 STC89C52 单片机和 TX-1C 开发平台，成功实现了一套完整的超声波距离监测与安全预警系统。系统具备以下完整功能：

1. **实时距离测量**：通过 HC-SR04 超声波模块实现 2~400cm 非接触测距
2. **人体检测**：通过 HC-SR501 被动红外传感器实现人体存在检测
3. **分级报警**：四级告警策略（安全/注意/报警/强制），三色 LED + 蜂鸣器多维度输出
4. **双模式运行**：监控模式（声光全开）和静默模式（仅亮灯）
5. **报警记录**：10 条报警记录环形缓冲区，带时间戳，支持按键查看回放
6. **异常处理**：传感器卡死检测、自动复位、超时容错
7. **扩展支持**：OLED 显示屏驱动预留（I2C 接口，支持中文显示）

### 8.2 设计亮点

#### 亮点1：分层模块化软件架构

项目采用清晰的**驱动层 + 应用层 + 主控层**三层架构设计：
- **驱动层**（`drv_*`）：每个外设独立驱动文件，接口简洁统一
- **应用层**（`app_*`）：报警逻辑、记录管理独立封装
- **主控层**（`main.c`）：仅负责系统初始化和主循环调度

这种架构使代码复用性高、维护方便，新增外设或修改逻辑时不需要改动其他模块。

#### 亮点2：完善的传感器异常处理

针对 HC-SR04 的已知脆弱性（ECHO 引脚易卡死），设计了多级防护：
- **单次测量级**：前置 ECHO 电平检测 + 复位脉冲
- **多次测量级**：连续超时计数，3 次超时触发硬件复位
- **复位后**：特殊返回值（800）使上层应用显示复位状态

#### 亮点3：整数运算避免浮点

距离换算公式 `dist = time / 59` 使用纯整数除法替代浮点运算，在 51 单片机上显著减少代码体积和执行时间（51 单片机无硬件浮点单元，浮点运算需软件模拟，耗时巨大）。

#### 亮点4：按键长/短按复用

通过检测按键按下的持续时间，将同一按键（S18）复用作"上翻"和"下翻"两个功能，在按键资源有限的条件下提升了交互效率。

#### 亮点5：环形缓冲区报警记录

使用环形缓冲区存储报警记录，内存占用固定（10 条记录 × 5 字节 = 50 字节），写入效率 O(1)，新记录自动覆盖旧记录，适合嵌入式系统的资源约束。

## 9. 存在不足与未来展望

### 9.1 存在不足

| 不足 | 说明 | 影响程度 |
|------|------|---------|
| **无温度补偿** | 声速随温度变化（约 0.6m/°C），未补偿会导致测距误差 | 中（温度变化 >10°C 时误差明显） |
| **主循环阻塞式** | `Delay_ms(50)` 阻塞主循环，无法在等待期间处理其他任务 | 低（50ms 延迟对安全系统可接受） |
| **蜂鸣器节奏耦合** | 告警节奏依赖主循环周期，修改主循环延时需同步调整 | 低（注释中已标注） |
| **OLED 未完全集成** | OLED 驱动代码已编写但未接入主程序（`config.h` 中缺少 SCL/SDA 引脚定义） | 中（功能未启用） |
| **无数据导出接口** | 报警记录只能 LCD 翻阅查看，无法导出到 PC | 低（对嵌入式原型机可接受） |
| **无 EEPROM 存储** | 报警记录存储在 RAM 中，掉电丢失 | 中（可通过外接 EEPROM 或使用 STC 内部 EEPROM） |
| **HC-SR04 探测角度小** | 约 15° 锥角，存在探测盲区 | 低（单点测距场景够用） |

### 9.2 未来展望

#### 近期改进（1~2 周）

- **OLED 集成**：在 `config.h` 中定义 `SCL`（P3.6）和 `SDA`（P3.7）引脚，将 OLED 驱动接入主程序，实现中文状态显示（如"监控模式"、"距离：042cm"等）
- **温度补偿**：增加 DS18B20 温度传感器，根据环境温度修正声速计算公式 `v = 331.4 + 0.6T`

#### 中期改进（1~2 月）

- **非阻塞定时器调度**：使用定时器中断替代 `Delay_ms()` 实现时间片轮转调度，提高系统实时响应能力
- **I²C EEPROM 存储**：使用 AT24C02 保存报警记录，实现掉电不丢失
- **舵机云台扫描**：增加 SG90 舵机，使 HC-SR04 可旋转扫描，扩大探测范围

- **语音播报**：增加 SYN6288 语音合成模块，实现距离语音播报
- **多传感器融合**：增加第二路超声波或红外对射传感器，消除单点盲区
- **低功耗设计**：使用 STC 的低功耗模式，电池供电场景下延长续航
